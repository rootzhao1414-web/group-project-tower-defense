# 塔防 · 敌情雷达 v2

从设计稿（`ENEMY RADAR / BUILD DECK / DEPLOYMENT BRIEF`）反向抠出的**文案 + 数值 + 美术资产**，并落地成一版可独立运行的完整游戏。不依赖原仓库 `D:\group-project-tower-defense`，可单独打开，也可整目录拷进去覆盖。

## 运行

```bash
cd D:\deepseek\学习\tower-defense-v2
python -m http.server 8787
# 浏览器打开 http://127.0.0.1:8787/index.html
```

直接双击 `index.html` 也能跑；若报 `Script error.`，用上面的 http 方式看真实报错。

## MLP 炮塔部署建议

开波前点「预测下一波」，雷达显示按当前塔阵、金币和生命生成的敌人种类、数量，以及模型估计的漏怪数。点「部署建议」，游戏遍历买得起的塔种和空格，为每个候选方案扣除塔价、重新运行 A* 和智能配波，再交给模型打分。采用建议时，点击画布上黄色虚线框内的格子。加塔或卖塔后，按新布局重新预测。波次结束后，雷达会显示实际漏怪数。

**模型与标签。** 每条样本代表开波前的一种塔阵及其配波结果。Node.js 调用游戏的战斗逻辑跑完整波，记录实际抵达基地的敌人数。训练标签是漏怪数除以该波总敌人数。Python 用训练集拟合标准化参数，并用带 64、32 个神经元的两个 ReLU 隐藏层做监督回归。浏览器把预测比例限制在 0–1，再乘本波敌人数，比较预估漏怪数。预估改善超过 0.25 只时才推荐加塔。

**位置与怪物数据。** 特征包括波次、金币、基地生命、实际配波的敌人数量和血量，以及地面 A* 路线长度。每种塔的数量和位置通过射程内的路线长度编码。地面和飞行分开计算，路线前后半段也分别统计。对每种敌人，还估算这段覆盖能提供的伤害和减速。训练后导出标准化参数和权重，打开网页即可推理。

**适用范围。** 模型支持第 1–24 波，评估保留地面通路的单塔方案。模拟的波前炮塔从初始冷却状态开始，开波后不再追加建造。真实对局中跨波冷却、临时补塔或提前陷落都可能让观测值与预测不同。超出模型范围时仍可看下一波阵容。

### 验证结果

共生成 32,205 条游戏模拟记录，25,733 条用于训练，6,472 条留出测试。留出集的漏怪数平均绝对误差为 2.01 只。

另用 95 个新布局调用游戏里的全部候选评估，再运行真实战斗逻辑。保持原样、随机买塔、按 MLP 建议行动的平均实际漏怪数分别为 14.07、12.03 和 9.66 只。与保持原样相比，按建议行动有 68 局改善、26 局持平、1 局变差。

### 重新训练

从仓库目录运行，使用 Node.js 和 Python。游戏页面已经包含训练好的权重。

```sh
python -m pip install "scikit-learn==1.9.0"
node ml/simulate-deployment.cjs 1700
python ml/train-deployment.py
node ml/evaluate-deployment.cjs
```

模拟写入本地 `ml/deployment.jsonl`。训练时按整组布局留出 20% 用于评估，输出漏怪数的平均绝对误差和建议策略的实际漏怪数，并更新网页使用的 `deployment-model.js`。评估脚本用另一组布局运行网页的候选遍历逻辑，再把建议送回游戏引擎模拟。塔数值、战斗或配波逻辑更新后，可以用同一流程生成新权重。

### 特攻耦合（塔 × 敌人）

每座塔对每种敌人都有一张倍率表（`COUNTER`），命中结算走 `dmg = max(1, round(原始伤害 × 倍率) - 护甲)`：

- 倍率 ≥1.3 时命中冒橙色火花，告诉玩家「这一发打对了」。
- 减速时长也吃倍率（`SLOW_MUL`）：疾影 ×1.5、暗影君主 ×1.6、深渊巨像 ×1.2。

### 波次怎么生成

每波不再读固定蓝图，而是按玩家当前状态现场配比（`buildWave`）：

1. **看塔**：统计已建的塔，对波次池里每种敌人算反制力 `counter = Σ 塔数 × (伤害/间隔) × COUNTER[塔][敌]`
2. **找软肋**：反制力低于池内均值的敌人权重上调（`softness = clamp(1.55 - 比值×0.42, 0.45, 1.7)`）——只造炮塔，飞行单位就会暴涨
3. **看钱**：`budget = (7 + 波次×1.5) × (1 + 压力×0.25) + 金币×0.015`，攒钱等于给对面加预算
4. **boss 固定 1 只**，不参与预算分配，不会被压力系数放大成两三只

每波开始时把配比写进底栏：`第 4 波 · 空袭：虚空蝠×7 疾影×5 裂魂者×3（强度 17%）`。

### 经济：出售回收 + 金币利息

两套机制都是为了让「钱」流动起来，而不是越滚越死。

**出售**：点画布上已放置的塔选中它（脚下出现虚线圈与卖价），按 `X` 卖掉。

- 只能在两波之间卖，战斗中按 X 会提示「等这一波结束」
- 回收比例 = `0.42 + 波次×0.035 + 强度×0.08`，封顶 `0.8`，**永远低于原价**
- 残血塔折价：`成本 × 回收比例 × (1 - 0.35 × 掉血比例)`
- 例：第 1 波结束卖一座满血疾风弩塔（造价 30）得 13，第 6 波卖得 20

**利息**：每波清除时按手头金币结算，与奖励一起到账。

- 利率 = `0.05 + 波次×0.008 + 强度×0.03`，封顶 `0.15`
- 单波封顶 = `10 + 波次×5`，防止后期躺着吃利息
- 底栏提示：`✅ 第 2 波清除 · 奖励 +20 · 利息 +15`

两项都在 `design-assets.js` 的 `ECON` 里，改一个数就能整体调松紧。
