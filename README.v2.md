# 塔防 · 敌情雷达 v2

从设计稿（`ENEMY RADAR / BUILD DECK / DEPLOYMENT BRIEF`）反向抠出的**文案 + 数值 + 美术资产**，并落地成一版可独立运行的完整游戏。不依赖原仓库 `D:\group-project-tower-defense`，可单独打开，也可整目录拷进去覆盖。

## 运行

```bash
cd D:\deepseek\学习\tower-defense-v2
python -m http.server 8787
# 浏览器打开 http://127.0.0.1:8787/index.html
```

直接双击 `index.html` 也能跑；若报 `Script error.`，用上面的 http 方式看真实报错。

## CNN + MLP 炮塔部署建议

开波前点「预测下一波」，雷达显示敌人种类、数量和模型估计的漏怪数。点「部署建议」，游戏遍历买得起的塔种和空格，按候选塔阵重算地面 A* 路线，并按扣除塔价后的余额重新配波。用同一个模型给当前塔阵和候选塔阵打分。候选预计少漏超过 0.25 只时，雷达标出具体塔种和格子，玩家点击黄色虚线格确认建造。第 1–24 波可评估保留地面通路的单塔方案。

模型的地图输入是 6 × 9 × 16。前五层各表示一种炮塔占据的格子，第六层表示地面路线，沿路线从出生点到基地用 1–2 标记进度。两层 3 × 3 卷积提取格子之间的位置关系，池化后的特征与 67 项数值特征拼接。数值特征包括波次、金币、敌人血量、射程覆盖和估算减速等。两层全连接网络输出整波漏怪比例，乘以该候选波次总敌人数得到预估漏怪数。

离线生成样本时，游戏引擎为每个布局跑完整波，用漏怪数除以总敌人数得到标签。PyTorch 训练模型，导出 JSON 权重，由浏览器用 JavaScript 前向推理。暗影君主等 Boss 波也走同一个推理流程。雷达按预计漏怪数排序，金币用于限定可选塔种和更新配波。实战结算显示实际漏怪数。

### 重训和评估

在仓库目录使用 Node.js 和装有 NumPy、PyTorch、scikit-learn 的 Python。四个随机种子分别生成 1,000 个起始布局及其候选方案。训练集、验证集和测试集按起始布局分组。验证集选择训练轮次，测试集用于报告误差。

```sh
node ml/simulate-deployment.cjs 1000 260624
node ml/simulate-deployment.cjs 1000 270624
node ml/simulate-deployment.cjs 1000 280624
node ml/simulate-deployment.cjs 1000 290624
python ml/train-deployment.py
node ml/evaluate-deployment.cjs 96
node ml/evaluate-deployment.cjs 384 --fast-boss
```

生成的 `ml/cnn-*.jsonl` 留在本地。训练脚本更新网页读取的 `deployment-model.js`。离线评估脚本先调用网页的推荐逻辑，再将建议送入游戏引擎核验实际漏怪数。用 `--mlp-only --output <路径>` 可以在相同数据拆分上训练纯 MLP 对照，再用 `node ml/evaluate-deployment.cjs 96 --model <路径>` 测试。

### 实验结果

四批共生成 76,090 条模拟记录，其中 52,508 条训练、8,763 条验证、14,819 条测试。两个模型使用同一数据拆分。

| 模型或策略 | 测试集漏怪数 MAE | 高速 Boss 波漏怪数 MAE | 95 个额外布局平均实际漏怪 |
|---|---:|---:|---:|
| 纯 MLP（同数据重训） | 1.58 只 | 1.68 只 | 9.59 只 |
| CNN + MLP | 1.31 只 | 1.31 只 | 9.46 只 |
| 随机买塔 | — | — | 11.95 只 |

在 47 个额外高速 Boss 布局里，保持原样时平均漏怪 15.06 只，按 CNN + MLP 建议后为 9.55 只，Boss 突破从 47 次降到 45 次。单塔建议在这批布局中主要减少了普通敌人漏怪。

### 特攻耦合（塔 × 敌人）

每座塔对每种敌人都有一张倍率表（`COUNTER`），命中结算走 `dmg = max(1, round(原始伤害 × 倍率) - 护甲)`：

- 倍率 ≥1.3 时命中冒橙色火花，告诉玩家「这一发打对了」。
- 减速时长也吃倍率（`SLOW_MUL`）：疾影 ×1.5、暗影君主 ×1.6、深渊巨像 ×1.2。

### 波次怎么生成

每波不再读固定蓝图，而是按玩家当前状态现场配比（`buildWave`）：

1. **看塔**：统计已建的塔，对波次池里每种敌人算反制力 `counter = Σ 塔数 × (伤害/间隔) × COUNTER[塔][敌]`
2. **找软肋**：反制力低于池内均值的敌人权重上调（`softness = clamp(1.55 - 比值×0.42, 0.45, 1.7)`）——只造炮塔，飞行单位就会暴涨
3. **看钱**：`budget = (7 + 波次×1.5) × (1 + 压力×0.25) + 金币×0.015`，攒钱等于给对面加预算
4. **boss 固定 1 只**，不参与预算分配，不会被压力系数放大成两三只

每波开始时把配比写进底栏：`第 4 波 · 空袭：虚空蝠×7 疾影×5 裂魂者×3（强度 17%）`。

### 经济：出售回收 + 金币利息

两套机制都是为了让「钱」流动起来，而不是越滚越死。

**出售**：点画布上已放置的塔选中它（脚下出现虚线圈与卖价），按 `X` 卖掉。

- 只能在两波之间卖，战斗中按 X 会提示「等这一波结束」
- 回收比例 = `0.42 + 波次×0.035 + 强度×0.08`，封顶 `0.8`，**永远低于原价**
- 残血塔折价：`成本 × 回收比例 × (1 - 0.35 × 掉血比例)`
- 例：第 1 波结束卖一座满血疾风弩塔（造价 30）得 13，第 6 波卖得 20

**利息**：每波清除时按手头金币结算，与奖励一起到账。

- 利率 = `0.05 + 波次×0.008 + 强度×0.03`，封顶 `0.15`
- 单波封顶 = `10 + 波次×5`，防止后期躺着吃利息
- 底栏提示：`✅ 第 2 波清除 · 奖励 +20 · 利息 +15`

两项都在 `design-assets.js` 的 `ECON` 里，改一个数就能整体调松紧。
