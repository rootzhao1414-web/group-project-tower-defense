# 外接智能体：一个零改动的闭环评测

> 主线的指标是「单波漏怪预测误差」（测试集 MAE 1.31），但没有人回答另一个问题：
> **这套建议放到实际对局里，能撑到第几波？**
> 仓库里没有这个工具——网页上一次只给一条建议，靠人点着玩。
> `tools/agent-bench.mjs` 补上这一环：**不改一行游戏代码**，直接驱动 headless 的 `TDSimulation` 把整局跑到陷落。

## 1. 它怎么工作

游戏在 `typeof document === 'undefined'` 时会挂出 `window.TDSimulation`（`game.js` 末尾），
本工具用 `vm` 把它和模型一起加载进 Node，然后逐波循环：

```text
setup(布局) → 按策略补塔 → scenario().current() 取本波阵容 → run() → 读回余额/生命 → 下一波
```

用到的接口都很小：`setup`、`scenario`、`recommend`、`run`。
余额和生命没有专门接口，是通过模型输入的第 2、3 个特征（`[波次, cash, lives, ...]`）反读的——
这算是「模型输入透明」的一个副产品，不是正式 API。

## 2. 怎么跑

```bash
node tools/agent-bench.mjs                                   # 三种策略，单个种子
node tools/agent-bench.mjs --policy advisor --max-buys 4 --threshold 0
node tools/agent-bench.mjs --seeds 20261116,20261117,20261118 --max-buys 4 --out docs/bench-results.csv
node tools/agent-bench.mjs --policy advisor --json docs/bench-trace.json   # 逐波明细
```

参数：`--seed` / `--seeds`、`--waves`（默认 24）、`--threshold`（默认 0.25，与网页一致）、
`--max-buys`（每波最多买几座，默认 1）、`--policy`、`--out`（CSV）、`--json`（逐波 trace）。

## 3. 三种策略

| 策略 | 行为 |
|---|---|
| `none` | 不建塔，纯基线 |
| `random` | 每波在合法格子里随机补，预算与 advisor 相同 |
| `advisor` | 用 `TDSimulation.recommend()` 逐座挑「预计漏怪最少」的格子，改善小于阈值就停手 |

`advisor` 每买一座都会重新 `setup` 再重新排序，所以 `--max-buys 4` 等价于「这一波连续给 4 次建议」。

## 4. 结果（3 个种子 × 24 波上限）

| 策略 | 撑到第几波 | 累计漏怪 | 塔数 | 花费 | 结束时余金 |
|---|---:|---:|---:|---:|---:|
| 不建塔 | **2.0** | 22 | 0 | 0 | 171 |
| 随机铺塔（≤4/波） | **10.3** | 18 | 33 | 1667 | 3528 |
| 建议·每波 1 座（网页行为） | **9.0** | 20 | 9 | 555 | 1621 |
| 建议·每波 ≤4 座 | **17.7** | 32 | 27 | 1615 | 7765 |
| 建议·阈值 0，每波 ≤4 座 | **17.0** | 26 | 61 | 2662 | 3885 |

逐局数字见 [`docs/bench-results.csv`](bench-results.csv)。

## 5. 三个发现

**① 瓶颈是「每波买几座」，不是「买在哪」。**
同一个模型、同一批种子，只把每波购买数从 1 放宽到 4，波次从 9.0 涨到 17.7。
格子排序没变，变的是「愿不愿意在有钱的时候连续下单」。

**② 建议策略会囤金。**
三局结束时分别剩 12,054 / 5,513 / 5,728 金。
阈值 0.25 把「小幅改善」全挡在门外，而单步贪心看不到「先买一座、下一座才变好」这种组合收益——
钱花不出去，是当前推荐逻辑最直接的问题。

**③ 随机铺塔的方差极大。**
3 / 4 / 24 波。种子 20261118 用 86 座塔撑满了 24 波上限。
这说明在当前数值模型下，「塔的总投入量」本身就是很强的变量，选点质量不是唯一因素。
反过来看，建议策略赢在**稳定**（16–21 波），不是赢在**上限**。

## 6. 局限（必须和数字一起看）

- **结果偏乐观**：每波都用 `setup()` 重建布局，塔血量不跨波累积；真实对局里残血塔会被继承，通常更难。
- **24 波是模型上限**：`maxWave = 24`，超出的波次 `predict()` 直接返回 `null`，建议退化。
- **余额/生命是反读的**：用模型输入特征取数，属于观测技巧，不是稳定接口。
- **3 个种子**：只够看趋势，不够做统计结论。

## 7. 与外部 LLM 那条线的关系

桌面那份 LLM 托管版本（`TD_AGENT` + 本地桥接）跑在同一套 `TDSimulation` 上，
所以两者的成绩可以用同一坐标并排比较：**撑到第几波、累计漏怪**。

本次没有把 LLM 桥接并入仓库：它要 API Key、要联网、输出不确定，
而且历史日志有 1.2 MB，和「打开网页就能玩」的定位冲突。
这里只保留**可复现的那一半**：评测骨架。
