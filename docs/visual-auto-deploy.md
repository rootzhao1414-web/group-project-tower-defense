# 视觉自动部署

游戏的 CNN + MLP 模型按预计漏怪数推荐一座炮塔及其位置。视觉助手把玩家的两次操作连起来，先点击「部署建议」，再点击棋盘上出现的推荐格。每次由玩家发起，最多建造一座炮塔。

## 安装和运行

在 Windows 上准备 Microsoft Edge 和 Node.js 20 或以上版本。下载并解压本分支的代码，在项目目录运行以下命令。

```powershell
npm ci
npm start
```

以后也可以双击 `launch-auto-deploy.cmd` 启动。打开 Edge 游戏窗口后，在「敌情雷达」中点击「自动部署」。建塔成功时，雷达显示「已部署」和炮塔名称，金币按造价扣减，棋盘上的部署数量增加一座。接下来可继续手动选塔或点击「开始波次」。

直接打开 `index.html` 或访问 GitHub Pages 时，可点击「部署建议」并手动确认黄框。自动部署需要本地 Node.js 进程来截取游戏图像并操作 Edge。

## 识别和点击流程

1. **匹配按钮。** `auto-deploy.mjs` 截取雷达的按钮区域。`vision.mjs` 把截图和 `suggest_btn.png` 转成灰度，裁去模板边缘 4 像素，再滑动比对按钮字样。使用零均值归一化互相关，得分最高且大于 `0.8` 的窗口中心作为点击候选。这个分数是图像相似度。
2. **等待模型建议。** 助手通过 Playwright 点击候选位置，游戏照常计算塔种和推荐格。雷达显示「点击黄色格子部署」后，助手等待画布绘制推荐框。金币不足、本次改善不足或模型超出适用范围时，雷达显示游戏原有提示，流程在这里结束。
3. **查找推荐格。** 助手读取 `960 × 540` 的 Canvas 图像，每格 `60 × 60` 像素。推荐虚线框距格边 4 像素。逐格检查四条边，统计橙黄色像素的覆盖率。每条边覆盖至少 `40%`，且全棋盘只有一个符合条件的格子时，取该格中心。
4. **点击并确认。** 将图像像素按元素显示宽高映射到浏览器视口坐标，检查鼠标落点确实位于目标控件或棋盘上，然后点击。点击棋盘前再次检查雷达内容和按钮状态，部署是否成功以游戏返回的「已部署」消息为准。

棋盘识别使用的 HSV 范围如下。

| 分量 | 阈值 |
| --- | --- |
| 色相 H | `22°–44°` |
| 饱和度 S | 至少 `0.5` |
| 明度 V | 至少 `140/255` |

截图来源是当前游戏页面的雷达按钮区和棋盘画布，点击通过 Playwright 在游戏标签页内完成。自动部署请求串行执行。暂停或波次进行中，「自动部署」随「部署建议」一起变灰。

## 代码位置

| 文件 | 职责 |
| --- | --- |
| [`index.html`](../index.html) | 提供「自动部署」按钮和视觉助手状态提示 |
| [`auto-deploy.mjs`](../auto-deploy.mjs) | 启动 Edge，管理截图、点击坐标转换和状态检查 |
| [`vision.mjs`](../vision.mjs) | 对 PNG 像素执行按钮模板匹配和虚线框识别 |
| [`suggest_btn.png`](../suggest_btn.png) | 从游戏内截取的「部署建议」按钮模板 |
| [`game.js`](../game.js) | 计算部署建议、绘制推荐框、执行建塔和扣费 |
| [`package.json`](../package.json) | 声明运行命令和 Node.js 依赖版本 |

## 验证与维护

- 新开一局点击「自动部署」，检查雷达提示、金币和炮塔数量。等待几秒，确认这次操作只建了一座塔。
- 暂停后查看「自动部署」是否变灰；恢复后开始波次，进行中的波次也应禁用按钮。
- 新开一局手动建四座疾风弩塔，花完初始 120 金，再点击「自动部署」。雷达应提示金币不足，棋盘上的塔应为四座。
- 显示「未能从雷达图像识别」时，将浏览器缩放恢复到 100%。如果修改过按钮文字、字体或样式，运行 `npm run capture-template`，重新启动演示并重试。
- 如果修改棋盘尺寸、每格像素数、推荐框内边距或颜色，同步更新 `vision.mjs` 的几何参数和颜色阈值。出现黄框却无法识别时，可在游戏中手动点击推荐格。
